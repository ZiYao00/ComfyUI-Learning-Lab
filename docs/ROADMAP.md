# ComfyUI Learning Lab Roadmap

> Roadmap 负责阶段方向；可执行任务和勾选状态统一维护在 [TASKS.md](TASKS.md)。

## Phase 0 - 项目基础

状态：**基本完成**。

已完成：

- 项目命名与目录边界。
- Obsidian Vault 基础结构。
- `00-导航.md` 作为知识入口。
- 单一 Markdown 内容源原则。
- 模型主说明书优先原则。
- 独立 Git 仓库，默认分支 `main`。
- `.gitignore` 与本地备份隔离规则。
- 旧 `comfyui.backup` 初步迁入 `_legacy/`。

待收尾：

- 明确 `.obsidian` 的版本控制边界。
- 人工确认后完成首次 Git commit。

## Phase 1 - MiniMax H3 实际验证

状态：**基础说明书完成，进入 RH / RTX 4090 实测阶段**。

目标不是继续补理论，而是用真实工作流验证当前文档是否好用。

重点：

- FL2VA I2V 实测。
- Ref2VA 多参考实测。
- Turbo / 非 Turbo 对比。
- 显存、时长、分辨率、steps、生成时间记录。
- 真实失败案例与修复方式。
- 根据实测决定是否需要独立“实战 / 故障排查”附页。

## Phase 2 - 旧资料选择性迁移

状态：**已建立暂存区，待逐项复核**。

历史 `comfyui.backup` 已按目录名 / 文件名初步整理到 `vault/_legacy/`。

原则：

- `_legacy` 是待整理区，不是正式知识区。
- 不要求把所有旧文件迁完。
- 只迁移仍有价值、且当前确实会使用的内容。
- 每次迁移必须重新核对当前资料或实际运行结果。
- 迁移后的正式内容不保留“旧笔记原样复制”的痕迹，应按当前说明书式结构重写。

优先候选：

- Foundations：安装、报错、尺寸、模型路径。
- Video：Wan、Hunyuan、LTX 等视频模型旧笔记。
- Plugins：高频插件 / 节点。
- Prompts / Training：提示词基础、LoRA 训练。

## Phase 3 - 第二个模型样板

选择一个**实际会使用、且结构与 H3 差异明显**的模型。

目标：验证“单文件说明书”是否仍适用，并暴露 H3 样板无法代表的情况。

完成后比较：

- 哪些信息是真正通用的。
- 哪些字段只属于某类模型。
- 哪些内容应该放主文档。
- 哪些内容达到什么复杂度才值得拆页。

## Phase 4 - Model Learning Template v1

至少完成两个真实模型样板后再正式制定。

模板重点不是固定章节数量，而是规定：

- 信息优先级。
- 主说明书阅读顺序。
- 下载 / 安装路径 / 文件作用的表达方式。
- 来源与 `last_verified` 规则。
- 参数与实测记录格式。
- 何时拆分实战、故障排查等附页。

## Phase 5 - 学习体系扩展

只有真实内容增长到需要时，再建立正式分类：

- `Plugins/`
- `Workflows/`
- `Foundations/`
- 其它真正需要的学习模块。

不提前建立百科式空目录。

## Phase 6 - 网站原型

至少已有 3 个稳定学习模块后再启动。

方向：

- `vault/` Markdown 继续作为唯一内容源。
- 评估 Quartz 等静态发布方案。
- 网站负责导航、搜索、学习路径和移动端阅读。
- 明确公开内容与个人私有内容边界。

网站是展示层，不维护第二套正文。
