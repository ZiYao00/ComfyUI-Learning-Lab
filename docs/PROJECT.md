# ComfyUI Learning Lab 项目说明

## 项目定位

ComfyUI Learning Lab 是一个面向长期学习的 ComfyUI 知识体系项目。

它不是：

- ComfyUI 官方文档替代品。
- 模型百科数据库。
- 插件注册表。
- 单纯的工作流收藏夹。

它关注的是：

> 如何把一个复杂的 AI 工作流知识点，整理成可以理解、实践、复习、讲解的学习模块。

## 核心方法

每个学习模块尽量回答：

1. 它是什么？
2. 为什么需要它？
3. 它解决什么问题？
4. 容易和什么概念混淆？
5. 在 ComfyUI 中什么时候使用？
6. 实际验证结果如何？
7. 如何快速复习？

## 内容原则

### 主讲义优先

对于“已有基础、主要用于快速复习”的模型知识点，默认先做 **一篇自包含主讲义**，阅读顺序应尽量符合实际使用：

> 下载什么 → 放哪里 → 每个文件做什么 → 模式怎么选 → 常见参数 → 易错点 → 30 秒复习。

当内容继续增长时，不写“第 2 篇 / 第 3 篇”，而是保持 **一个模型 = 1 篇主说明书 + 若干按需附页**：

- 主说明书始终作为模型入口，保留相对稳定、需要快速复习的核心知识。
- 提示词、加速优化、实测记录、故障排查等更新频率或使用场景明显不同的内容，复杂到影响主说明书阅读时再拆页。
- 可直接复用的 Agent 指令、模板等放入模型目录下的 `resources/`，不与学习正文混写。
- 不为了模块化而模块化；只有真实内容增长到需要时才拆。

### 学习优先

不追求收录所有内容，只记录值得掌握的知识。

### 实验优先

重要参数、显存、工作流选择，需要通过实际运行不断修正。

### 单一知识源

Obsidian Markdown 是内容源。

未来的网站、HTML、PDF 都应该由 Markdown 生成，而不是维护多份正文。

### 版本意识

ComfyUI、模型和节点变化快速，重要资料记录验证日期。

### 信息设计与版式系统

学习页不只要求“内容正确”，还要支持快速扫描、横向比较和低成本回看。

项目使用 `docs/DESIGN-SYSTEM.md` + `vault/.obsidian/snippets/learning-lab.css` 维护统一视觉语言：

- Markdown / Wikilink / Callout 负责内容语义与关系。
- CSS 负责标题层级、留白、Card、Grid、Badge、表格、说明块和响应式布局。
- 需要比较的对象优先横向组织；2~3 项使用双栏 / 三栏，固定字段比较优先表格。
- 教程 / 社区信息、项目判断和真实实测必须有不同状态表达，不能混成同一种视觉权重。
- `resources/` 中的原始指令与源材料以完整、易复制为先，不强制套学习页视觉组件。
- 未来 Quartz / Starlight 复用相同内容语义，不为了网站提前维护第二套正文。

### `.obsidian` 版本控制边界

当前仓库只把**可复用的项目级 CSS Snippet**视为需要共享的 Obsidian 配置；机器状态和个人工作区状态继续保持本地：

- 跟随仓库：`.obsidian/snippets/` 中项目需要的 CSS。
- 不跟随仓库：`workspace.json`、`workspace-mobile.json`、`cache/` 等机器状态。
- 其它主题、插件启用状态和个人偏好暂不默认纳入项目规范，只有未来确实需要复现时再单独评估。

## 当前样板

第一阶段使用 MiniMax H3 作为样板。基础内容曾先验证“单文件说明书”是否适合快速复习和讲解；随着提示词、加速与实测内容增长，H3 现已进入“主说明书 + 按需附页”的第二阶段样板。

### 模板策略

现在**不正式制定模板**。

原因：只用一个模型抽象模板，容易把 MiniMax H3 自己的特征误当成所有模型的通用结构。

当前只保留几条临时规则：

- 一个模型优先一篇主说明书。
- 开头直接给下载 / 安装 / 文件作用等可执行信息。
- 实战、实验、故障排查足够复杂时再拆附页。
- 保留最后验证日期和官方来源。
- 正式学习页使用 Learning Lab Design System，但先判断信息关系，再选择 Card / Grid / Table / Callout，不套固定视觉模板。

完成 H3 的实际工作流验证，再至少整理一个不同类型的模型；比较两个样板后再形成 `Model Learning Template v1`。
